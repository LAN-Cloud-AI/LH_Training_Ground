# LeadsHunter模型训练场 · 运行手册

## 环境

- Python ≥ 3.11
- 可选：TikHub Token、DeepSeek API Key（见 `.env.example`）
- **勿**用本机训练场 `.env` 覆盖生产 `agent/.env.local`

## 场景 vs 产品

- **场景 `new_car`**：通用主机厂新车情感规则（skill/schema）。  
- **产品 `mona_l03` 等**：训练/爬取用的车型词表；可随时加第二款、第三款新车。  
- 金标尽量标在 `new_car` 下，以提升跨车型泛化；Mona 帖可在金标里加 `case_product: mona_l03`。

```bash
csl-lab list-products --scenario new_car
csl-lab crawl --scenario new_car --product mona_l03
csl-lab judge --scenario new_car --product mona_l03 --posts data/posts/xxx.jsonl
```

## 数据目录

| 路径 | 内容 |
|------|------|
| `data/posts/` | 爬取 PostRecord JSONL |
| `data/judgements/` | 初判结果 |
| `data/review_queue/` | AI 审核队列 |
| `data/crawl_logs/` | 爬取事件日志 |
| `data/eval_reports/` | 评估报告 |
| `gold/new_car/` | 新车场景金标（版本化） |

`data/**` 默认 gitignore。

## 推荐节奏

1. `dry-run --scenario new_car --product mona_l03`  
2. 小批量真爬 Mona（或其它产品案例）  
3. 人审金标写入 `gold/new_car/`（强调通用标签，少写死车型特例）  
4. 改 `scenarios/new_car/skill.md` → `eval`  
5. 换第二款车只加 `products/*.yaml`，用同一 skill 验证泛化  

## 与大 Agent 合并

合并前勿改生产 `lh-agent run-once`。合并清单见技术方案 §7。
